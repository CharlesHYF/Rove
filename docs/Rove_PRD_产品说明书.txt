01 背景与问题
现有 Agent Web 能力高度碎片化：Search、Crawl、Browser、Extract、Index、Vector Retrieval、Rerank 与 Citation 往往由不同组件承担，缺少统一 Runtime、Document Model、错误语义和可观察性。Rove 通过自研完整链路，把 Web 转化为 Agent 可检索、可引用、可调试的 Evidence。
产品问题定义
如何让任意 Agent 在不依赖外部 Search SaaS 的前提下，可靠地发现 Web 内容、访问动态页面、建立自己的索引，并以结构化 Evidence 的形式获得高质量检索结果？
02 产品目标与非目标
产品目标
提供从 Crawl → Fetch → Parse → Index → Retrieve → Rank → Evidence 的完整闭环。
默认自托管，搜索结果来自 Rove 自己维护的 Elasticsearch Index。
统一静态 Web 与动态 Web 的访问模型，采用 HTTP First、Browser Escalation。
在没有任何 LLM API Key 的情况下仍可完成抓取、索引、BM25 检索、基础 Hybrid 流程与 Evidence 输出。
为开发者提供优秀的 CLI/TUI Debug Experience，为 Agent 提供 JSON/JSONL/MCP。
所有核心组件均可观测、可测试、可独立演进。
非目标
不建设 SaaS Dashboard、Billing、多租户和商业化账号体系。
不做通用 Agent Framework、Chatbot 或 Deep Research 应用。
不以第三方 Search Provider 作为产品成立前提。
不在 Core 中强绑定某个 LLM、Embedding 或 Reranker 供应商。
不要求 Kubernetes 才能运行。

04 产品原则
原则
要求
Open
核心能力可以本地/自托管运行；Apache-2.0。
Self-owned Retrieval
Crawler、Index、Retriever、Ranker 属于 Rove Core。
HTTP First
优先轻量 HTTP；只在必要时启用 Chromium。
Deterministic First
无 LLM 依赖也必须形成完整基本闭环。
Agent-first
输出 Evidence，而不是面向人的 SERP。
Human-debuggable
每个重要决策和耗时都可在 CLI/TUI/Trace 中查看。

TUI
直接运行 rove 进入 TUI。TUI 的定位不是营销界面，而是 Rove Runtime Debugger。必须提供 Search、Crawl、Browse、Index、Runtime 五个主要视图。
视图
核心信息
Search
结果、Evidence、lexical/vector/fusion/rank 分数、耗时
Crawl
Frontier、active workers、visited、failed、host rate
Browse
Page State、interactive elements、actions、navigation
Index
documents、chunks、index size、alias、health、indexing throughput
Runtime
HTTP、Browser、ES、Cache、SQLite、Trace 状态
MCP
MCP 对外暴露稳定的 Agent Tool，而不是内部组件细节。至少包括 rove_search、rove_fetch、rove_browse、rove_crawl、rove_extract。

09 非功能需求
ID
类别
要求
NFR-001
可用性
核心组件异常必须返回 machine-readable error，不允许 silent failure。
NFR-002
性能
本地常规环境 Search 目标 P50 < 200ms、P95 < 500ms，不计外部 embedding API。
NFR-003
并发
Crawler 与 HTTP Fetcher 使用有界并发；Browser Session 必须复用。
NFR-004
可扩展
组件通过接口隔离；Embedder、Reranker、Parser 可替换。
NFR-005
可观测
所有核心操作具备日志、metrics、trace_id 与阶段耗时。
NFR-006
可移植
Linux/macOS 优先；CLI Core 以单 Go Binary 分发。
NFR-007
数据一致性
Document/Chunk 写入需幂等；失败批次可安全重试。
NFR-008
资源保护
必须限制 body size、crawl pages、host concurrency、browser sessions。
10 安全与合规
默认阻止 file://、localhost、127.0.0.0/8、RFC1918 私网、云 Metadata Endpoint，显式 allow-private 才可放开。
限制 Redirect、Response Size、Decompression、Download、Crawl Depth 与 Max Pages。
默认尊重 robots.txt，并支持 per-host concurrency 与 crawl delay。
Browser Runtime 对下载、文件系统访问与执行权限实施最小权限策略。
敏感配置不得进入普通日志；Trace 中需要脱敏 URL 参数和 Header。

12 优先级与验收标准
P0/P1/P2 仅用于施工优先级，不代表不同产品架构。Rove 从一开始即按完整 Acquisition → Runtime → Content → Index → Retrieval → Evidence 架构设计。
级别
定义
代表能力
P0
Rove 核心闭环不可缺少
Crawler、HTTP/Browser、Content、ES、BM25/Vector/Hybrid、Ranking、Evidence、CLI/TUI
P1
完整架构中的高级能力
Map、Query Router、Reranker、Vertical Index、MCP、Index migration tooling
P2
增强生态与规模化能力
更多 Parser、分布式 Scheduler、插件协议、更多部署拓扑
核心验收
给定 Seed URL，Rove 能 discover → fetch → parse → extract → deduplicate → index。
动态网页在 HTTP 内容不足时能够自动 Browser Escalation，并把结果进入同一 Document Pipeline。
rove search 的结果来自 Rove 自己的 Elasticsearch Index，不要求 Exa/Tavily 等外部 Search API。
查询支持 BM25 与 Vector 候选，并可经 Hybrid Fusion 输出统一结果。
结果至少包含 URL、source、relevant chunk、score，可直接被 Agent 作为 Evidence 使用。
开发者可以从 TUI 观察 Crawler、Browser、Index、Search Score、Evidence 和关键耗时。
13 成功指标与风险
成功指标
维度
核心指标
Developer Adoption
被 Agent 项目作为 Web Infrastructure Dependency 使用
Retrieval Quality
Top-K relevance、Evidence usefulness、freshness、source diversity
Reliability
crawl success、fetch success、indexing success、search availability
Debuggability
关键失败可定位到 acquisition/fetch/content/index/retrieval/ranking 任一阶段
Self-host Value
核心链路在无第三方 Search SaaS 情况下可完整运行
主要风险
风险
影响
应对
全 Web 规模过大
资源和抓取范围不可控
以可配置 Corpus/Seed/Vertical Index 为核心，严格 URL Policy
动态网页成本高
CPU/内存/延迟增加
HTTP First + Browser Pool + 有界 Session
检索质量不足
Agent Evidence 价值下降
BM25/Vector Hybrid、可观测 Ranking、离线 benchmark
ES 运维变重
本地安装门槛上升
官方 Docker Compose、health check、alias migration tooling
功能膨胀为 Agent Framework
产品边界模糊
Infra 原子接口；Research/Workflow 保持上层
